---
title: What is a feed?
order: 10
description: A feed makes events visible to members and guests, as a web page and as a calendar subscription.
---

:::note
Editors and admins can see feeds. Only admins can create and change them.
:::

A feed publishes one or more calendars of your club. It has a web page for everyone who knows the link, and a subscription address for calendar apps. You find feeds under **Publish**.

## What is in a feed?

- Only **published** events. Drafts stay internal.
- The events of all calendars you select for the feed. Archived calendars deliver no events.
- Holidays appear only in the web view, not in the calendar subscription.
- Optionally only certain audiences. Without a selection the feed contains all audiences.

## The three visibilities

| Visibility              | Who can see the calendar?                                                   |
| ----------------------- | --------------------------------------------------------------------------- |
| **Public**              | Anyone with the link. Search engines may find and list it.                  |
| **Link only**           | Anyone with the link, including non-members. Search engines do not list it. |
| **Private (protected)** | Only people who know the secret in the link.                                |

:::warning
**Link only** is not access protection. Whoever passes on the link passes on the calendar. For truly internal events use **Private (protected)**.
:::

## Calendar apps and updates

Calendar apps fetch the subscription address themselves, on their own refresh schedule. New or changed events therefore do not show up in every app right away. How to set up the subscription is described in [Subscribe to a calendar](help:publishing/subscribe).
