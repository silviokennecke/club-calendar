# Double Opt-In Email Verification

**Date:** 2026-06-28  
**Status:** Approved

## Overview

Self-registered users must verify their email address before they can log in. SSO users (Google, Microsoft, Apple) are trusted and bypass verification. Verification is implemented via a time-limited email link using a split-token pattern stored in a dedicated audit table.

---

## 1. Data Model

### `User` entity additions

| Field | Type | Default | Notes |
|---|---|---|---|
| `isEmailVerified` | `bool` | `false` | Set to `true` for SSO-created users and on successful verification |
| `createdAt` | `DateTimeImmutable` | `now()` | Auto-set in constructor; used by the cleanup command |

### New `EmailVerification` entity

| Field | Type | Notes |
|---|---|---|
| `id` | string(36), UUID v7 | Primary key; also the "selector" for split-token lookup |
| `user` | many-to-one → User | Cascade delete |
| `tokenHash` | string(255) | bcrypt hash of the raw verifier (via Symfony `PasswordHasherInterface`) |
| `expiresAt` | `DateTimeImmutable` | `now + 24 hours` |
| `usedAt` | `?DateTimeImmutable` | Set when the token is consumed successfully |
| `invalidatedAt` | `?DateTimeImmutable` | Set when a newer token is issued for the same user |

**Split-token pattern:**
- Raw token parts are `id` (UUID, stored plaintext as PK) and `rawVerifier` (`bin2hex(random_bytes(32))`, 64 chars, never stored)
- DB stores `bcrypt(rawVerifier)` in `tokenHash`
- Email link carries both as separate query parameters: `?id={id}&token={rawVerifier}`
- On verify: find row by `id`, then `password_verify($rawVerifier, $tokenHash)`

**"Latest token only" rule:**
- When a new `EmailVerification` is created, all prior rows for the same user where `invalidatedAt IS NULL` are updated: `invalidatedAt = now()`
- Old rows are retained for audit; a row is only valid if `usedAt IS NULL AND invalidatedAt IS NULL AND expiresAt > now()`

## 2. Backend API

### Changed: `POST /api/auth/register`

**Before:** created user, returned access + refresh tokens (instant login).

**After:**
1. Validate DTO (unchanged)
2. Check email uniqueness (unchanged)
3. Create `User` with `isEmailVerified = false`
4. Create new `EmailVerification` (24h expiry)
5. Send verification email
6. Return **202** `{"message": "check_your_email"}` — no tokens

### Changed: `POST /api/auth/login`

After validating credentials, if `user.isEmailVerified === false`:
- Return **403** with `{"error": "email_not_verified"}` (following existing error format conventions)

Otherwise: unchanged.

### New: `POST /api/auth/resend-verification`

- Body: `{"email": "user@example.com"}`
- Rate-limited: 3 requests per email address per hour (Symfony RateLimiter)
- If user not found, or already verified: return **204** silently (do not leak account existence)
- If found and unverified: invalidate prior rows, create new `EmailVerification`, send email, return **204**

### New: `GET /api/auth/verify-email`

Query params: `id={uuid}&token={rawVerifier}`

Steps:
1. Find `EmailVerification` by `id`
2. `password_verify($rawVerifier, $tokenHash)` — if false → redirect `?status=error&reason=invalid`
3. Check `invalidatedAt IS NULL` — if not → redirect `?status=error&reason=invalid`
4. Check `expiresAt > now()` — if expired → redirect `?status=error&reason=expired`
5. Check `usedAt IS NULL` — if used → redirect `?status=error&reason=already_used`
6. Set `usedAt = now()`, set `user.isEmailVerified = true`, flush
7. Redirect to `{FRONTEND_URL}/auth/verify-email?status=success`

All redirects go to the frontend. The backend does not render any HTML.

### Changed: `OAuthController` (`findOrCreateOAuthUser`)

When creating a new `User` via SSO: `user.isEmailVerified = true`. No verification email is sent.

## 3. Email Infrastructure

### Dependencies

- `symfony/mailer` (via `composer require symfony/mailer`)
- `mjml` npm package (already available via Node.js in the monorepo)

### Environment variables

| Variable | Purpose |
|---|---|
| `MAILER_DSN` | Transport (e.g. `smtp://localhost:1025` for local Mailpit, or Mailgun/SES DSN in prod) |
| `MAILER_FROM` | Sender address, e.g. `"Club Calendar <noreply@example.com>"` |

`DEFAULT_URI` is renamed to `BACKEND_URL` for clarity (same value, same purpose). `config/packages/routing.yaml` is updated to reference `%env(BACKEND_URL)%`. The `EmailVerificationMailer` uses Symfony's `UrlGeneratorInterface` with `ABSOLUTE_URL` to construct the verification link — no separate URL injection needed, since the router's default URI is already set from `BACKEND_URL`.

### MJML build pipeline

- **Source:** `backend/templates/email/verify_email.mjml`  
  Written in MJML markup with Twig variables and `|trans` filter calls. Not executed by Twig — it is a build artifact input.
- **Compiled output:** `backend/templates/email/verify_email.html.twig`  
  Generated by the MJML CLI. Twig expressions survive compilation untouched (MJML ignores `{{ }}` and `{% %}` syntax).
- **Build command:** `npm run mjml` in root `package.json`:
  ```
  mjml backend/templates/email/verify_email.mjml -o backend/templates/email/verify_email.html.twig
  ```
  Both source (`.mjml`) and compiled (`.html.twig`) files are committed to git.

### Translations

Email strings live in **JSON** translation files: `backend/translations/messages+intl-icu.en.json` and `messages+intl-icu.de.json`. Keys:

- `email.verify.subject`
- `email.verify.greeting` (with `{name}` placeholder)
- `email.verify.body`
- `email.verify.button`
- `email.verify.expiry_note`
- `email.verify.ignore_note`

The MJML template uses `{{ 'email.verify.greeting'|trans({'{name}': userName}) }}` etc.

**Locale fallback:** `framework.translator.fallbacks: ['en']` is set in `config/packages/translation.yaml`. If a user's language has no translation file (e.g. `fr`), Symfony falls back to `en` automatically.

**Pipeline check:** `backend/translations/**/*.json` is added to the root `lint-staged` config (prettier formatting), ensuring translation files are consistently formatted on commit.

### `EmailVerificationMailer` service

- Accepts `User` and the raw verifier string
- Builds the verification URL: `{BACKEND_URL}/api/auth/verify-email?id={id}&token={rawVerifier}`
- Creates a `TemplatedEmail` with:
  - `->subject($translator->trans('email.verify.subject', locale: $user->getLanguage()))`
  - `->htmlTemplate('email/verify_email.html.twig')`
  - `->locale($user->getLanguage())`
  - `->context(['userName' => $user->getName(), 'verificationUrl' => $url])`
- Dispatches via `MailerInterface`

## 4. Frontend Changes

### `SignupPage.tsx`

After a successful register (HTTP 202), the signup form is replaced by an inline "Check your email" state (no new route). Displays the user's email address. No tokens are stored; the user is not logged in.

### `LoginPage.tsx`

Detects HTTP 403 with `{"error": "email_not_verified"}`. Shows an alert with:
- "Please verify your email before logging in."
- A "Resend verification email" button that calls `POST /api/auth/resend-verification` and shows a brief confirmation.

### New page: `/auth/verify-email`

Reads `?status` and `?reason` query params. Renders:
- `status=success`: "Your email is verified." + link to `/login`
- `status=error&reason=expired`: "This link has expired." + prompt to request a new one (link to `/login`)
- `status=error&reason=invalid` / `already_used`: "This link is not valid." + link to `/login`

### i18n

New keys added to `frontend/src/locales/en.json` and `de.json` covering all new strings (signup success state, login error, verify-email page states, resend confirmation).

## 5. Cleanup Command

**Class:** `App\Command\PruneUnverifiedUsersCommand`  
**Console command:** `php bin/console app:prune-unverified-users`

Logic:
- Delete `User` entities where `isEmailVerified = false` AND `createdAt < now() - 30 days`
- Cascade delete removes associated `EmailVerification` rows automatically

Intended to be scheduled via system cron (e.g. daily). No Symfony Scheduler component required.

## 6. Testing

### PHPUnit integration tests (`backend/tests/Controller/`)

- Registration returns 202, no tokens
- **Registration sends a verification email** — `MailerInterface` is replaced by a mock (Symfony's `InMemoryTransport` or PHPUnit mock); the test asserts exactly one message was dispatched with the correct recipient and subject
- Login with unverified account returns 403 `email_not_verified`
- Resend verification: 204, silently 204 for unknown/verified email
- Verify-email: success, expired, invalid, already-used cases
- SSO creates user with `isEmailVerified=true`

**Mocking approach:** bind `MailerInterface` to `symfony/mailer`'s `InMemoryTransport`-backed mailer in `config/packages/test/mailer.yaml` (`dsn: in-memory://default`). Tests retrieve sent messages via `$this->getContainer()->get('mailer.message_logger_listener')` or by injecting the transport, and assert message count / recipient / subject without any real SMTP call.

### E2E Playwright tests

Not required for this flow (email sending cannot be reliably E2E tested without a test SMTP service).

## Out of Scope

- Passkey registration (users with passkeys only, no password/email — not addressed)
- Email change verification (separate future feature)
- Admin-forced re-verification
