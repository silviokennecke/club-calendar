## INFO / hardening

- **I3 Misc backend**: fixtures password `password123` (`AppFixtures.php`; dev and CI only); `app:prune-unverified-users` is documented as a cron job in `docs/ops/OPERATIONS.md`, nothing in the repo (image, compose) schedules it; the refresh token is a hand-built HS256 JWT-shaped string with standard base64 rather than base64url (`TokenService.php:70-74`; verification is a raw HMAC compare with `hash_equals`, no `alg` parsing); `OidcProvider` sends no PKCE to the identity provider (the browser binding of the login code, L13, is separate); local `config/jwt/public.pem` is 0666 (a public key; created by the key generator under the dev machine's umask, other local files have the same mode; not set by repo code, `docker/entrypoint.sh` has no chmod; file modes inside a container not verified); 404-vs-403 existence oracle on club and calendar ids (unknown id 404, existing non-member 403; UUIDv7, not guessable). [BACKEND-F14, AUTH-Info, AUTHZ-F8/F9]
- **I4 Frontend**: route guards are client-side only (`ProtectedRoute`; the backend enforces); ids are placed into API paths without `encodeURIComponent` in most call sites (e.g. `useCalendarData.ts`, `InviteSection.tsx`; ids are server-generated UUIDs; the profile SSO link/unlink calls do encode); the OAuth provider id is put into the sign-in `href` unencoded (`SignInPage.tsx`, value from `/api/auth/providers`); the legacy `accessToken` sessionStorage key is still read (`api.ts`). [FRONTEND-F7/F9, F4]
- **SCAN-12 (residual)**: the release workflow's `ci` call keeps `contents: write` because the called `ci.yml` declares it for `autofix` (skipped on tags). Details: `04-scans-config.md`.
