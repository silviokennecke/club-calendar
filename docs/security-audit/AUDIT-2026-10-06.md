## HIGH

### H1 — No roles in clubs: any member can delete the club or remove everyone  [AUTHZ-F1]
- **Attack scope:** authenticated club member (e.g. a helper, or a compromised member account)
- **Description:** `ClubUser` is just (club, user); all club-level routes need only `CLUB_MEMBER`. Any member can delete the club (cascades to calendars, events, feeds), remove any member including the creator, add anyone, delete calendars, delete/regenerate feeds. No audit trail, no recovery.
- **Affected:** `ClubController.php:64-110`, `ClubService.php:69-116`, `ClubUser.php`, `CalendarController.php:80-89`, `FeedController.php:53-69`, voters
- **Fix:** add `role` (owner/admin/editor) to `ClubUser` + role voter; admin for member/calendar/feed-secret management, owner for club deletion/ownership transfer; forbid removing/demoting the last owner; migration setting owners for existing clubs.
- **Notes:** CWE-269/285. Known gap in `docs/redesign/BACKEND-GAPS.md`. Confidence high.

### H2 — Pre-account hijacking: attacker's password survives e-mail verification  [AUTH-1]

> **Status (git-log check 2026-10-15): PARTIALLY FIXED** — password reset added in `223a8d1`/`e55e266` (hashed single-use token, ends all sessions, confirms the address), so the victim can recover. At HEAD verification still keeps the attacker's password (`EmailVerificationService::revokeUnprovenSsoAccess` only) and registration is not pending-until-verified. **Still open: the core takeover path.**
- **Attack scope:** unauthenticated remote; needs a click on the genuine mail, or a mail link scanner issuing the GET
- **Description:** `POST /auth/register` stores an attacker-chosen password for any address and mails a link to the owner. `GET /auth/verify-email` marks the address verified but deliberately keeps the password (`revokeUnprovenSsoAccess`). Attacker then logs in as the verified victim. No password reset exists, so the victim cannot recover; later Google SSO links to the already-verified account without revoking anything. Attacker sees all clubs, calendars and private feed secrets. Also grants access when an admin adds the victim via `addMember`.
- **Affected:** `EmailVerificationService.php:52-101`, `AuthController.php:50-120`, `AuthService.php:28-44,192-201`
- **Fix (one of):** clear password on verification and make the owner set one via the mail token; keep registrations pending until verified (re-registration overwrites); make verification a POST from a frontend page (defeats scanners). Add password reset; bump `tokenVersion` on verification.
- **Notes:** CWE-287/640. Confidence high (behaviour is intentional per code comment).

### H3 — Anonymous Mapbox proxy: billing/quota abuse and disk-filling cache  [BACKEND-F1]
- **Attack scope:** unauthenticated remote
- **Description:** `MapboxController::proxy` has no auth; `access_control` is empty. Allow-list patterns `^/styles/`, `^/fonts/` are `rate_limited: false` and `^/styles/` includes the billed Static Images API. 2xx/404/410 responses are cached 30 days keyed by path + arbitrary query string, and cache hits bypass the limiter. Looping with `?r=$i` burns the operator's Mapbox quota and creates unbounded cache files (disk/inode exhaustion → outage). `/v4/` uses a global 2500/day budget one client can exhaust for all clubs.
- **Affected:** `MapboxController.php:29-52`, `Service/Map/MapboxProxyService.php:29-57,117-120`, `config/services.yaml:12-21`, `security.yaml:20-24`, `cache.yaml`
- **Fix:** require auth or per-IP limits (also on `rate_limited: false` routes); whitelist/normalise query params in cache key; cache only 2xx; bound the cache (Redis/APCu max size); narrow `^/styles/`, exclude `/static/`.
- **Notes:** CWE-770/306. Confidence high.

### H4 — Microsoft SSO issues sessions for unverified e-mail claims; addMember accepts them  [AUTH-2]
- **Attack scope:** unauthenticated remote with an attacker-owned Entra tenant (tenant `common`)
- **Description:** With no existing user, `findOrCreateOAuthUser` creates one with the claimed e-mail and `isEmailVerified=false` and still returns tokens. `ClubService::addMember` looks up by e-mail without checking verification. Attacker sets Entra `mail` to `kassenwart@verein.de`, signs in, and gets club access once an admin adds that address.
- **Affected:** `AuthService.php:171-218`, `OAuthController.php:84-97`, `ClubService.php:86-103`, `services.yaml:2-3`, `knpu_oauth2_client.yaml:21-32`
- **Fix:** no session for unverified SSO users until a verification mail is confirmed; ignore unverified users in e-mail lookups; replace direct add with accepted invitations; for Microsoft use `xms_edov` or restrict the tenant.
- **Notes:** CWE-290 (nOAuth). Confidence medium-high; exploitability depends on Entra app registration (Entra omits unverified-domain claims by default for newer apps).

## MEDIUM

### M2 — Verification/other links built from request Host header  [BACKEND-F2]
- **Scope:** unauthenticated remote (needs vhost forwarding unknown Hosts)
- **Description:** `EmailVerificationMailer` generates `ABSOLUTE_URL` from the request context; `default_uri` applies only in CLI; no `trusted_hosts`/`trusted_proxies`. Attacker registers victim's address with `Host: attacker.tld`; the genuine mail links to attacker host, who replays the token on the real host (combines with H2).
- **Affected:** `EmailVerificationMailer.php:36-41`, `framework.yaml`, `routing.yaml`
- **Fix:** `framework.trusted_hosts` from env; build links from `BACKEND_URL`; configure `trusted_proxies`; vhost rejects unknown Hosts.
- **Notes:** CWE-640/444.

### M3 — ICS injection via `X-APPLE-STRUCTURED-LOCATION`  [BACKEND-F3]
- **Scope:** authenticated user (calendar member); impacts all feed subscribers
- **Description:** location name/street/zip/city/country are concatenated raw into `X-TITLE="…"`/`X-ADDRESS="…"` and spliced into the ICS via `preg_replace`. CR/LF/`"`/`;` allowed by input validation → attacker injects properties/components (VALARM with URL, forged ORGANIZER/VEVENT, broken feed). `$2` in the value also gets interpreted by the replacement string (verified).
- **Affected:** `IcsService.php:46-66,184-215`, `LocationService.php:26-35,46-66`, `Service/Input.php`
- **Fix:** emit via eluceo Property/ParameterBag API instead of string splicing; reject control chars in `Input::string/nullableString`; at minimum `preg_replace_callback`.
- **Notes:** CWE-93/74.

### M4 — No CSP / security headers; tokens in sessionStorage  [FRONTEND-F1, BACKEND-F4]

> **Status (git-log check 2026-10-15): PARTIALLY FIXED** — `Referrer-Policy: no-referrer` for `/feed/*` (`75a3009`). **CSP, frame-ancestors, nosniff, HSTS, Permissions-Policy still missing.**
- **Scope:** unauthenticated remote (amplifies any XSS; clickjacking)
- **Description:** `.htaccess` sets only Cache-Control: no CSP, X-Frame-Options/frame-ancestors, nosniff, Referrer-Policy, HSTS, Permissions-Policy. Any future XSS = token theft (access + 7-day refresh). `index.html` has an inline theme script, so strict CSP needs hash/nonce. (Headers may exist at the vhost — unverified.)
- **Affected:** `backend/public/.htaccess`, `frontend/index.html`
- **Fix:** add CSP (`default-src 'self'`, Mapbox hosts, `frame-ancestors 'none'`), nosniff, Referrer-Policy, HSTS.
- **Notes:** CWE-693/1021.

### M5 — SSO tokens (incl. 7-day refresh token) in redirect query string  [AUTH-4, FRONTEND-F2]
- **Scope:** local / requires log or history access
- **Description:** callback redirects to `/auth/callback?token=…&refresh_token=…`; lands in Apache access logs, proxy logs, history; the SPA only strips it after the `/me` call; no Referrer-Policy. Login CSRF / session fixation is also possible because the callback accepts any supplied token (FRONTEND-F3).
- **Affected:** `OAuthController.php:99-109`, `frontend/src/pages/AuthCallbackPage.tsx:20-40`
- **Fix:** redirect with a single-use ~60 s code exchanged via POST, or use the URL fragment; `history.replaceState` immediately; Referrer-Policy.
- **Notes:** CWE-598.

### M6 — Refresh tokens never rotated/revoked; logout is a no-op  [AUTH-3, FRONTEND-F4]
- **Scope:** requires prior token compromise (XSS, logs, device)
- **Description:** stateless HMAC tokens without `jti`/store/rotation/reuse detection; each refresh issues a new 7-day token while old ones stay valid → indefinite sessions. `/logout` does nothing server-side; `tokenVersion` only bumped in takeover paths; no "sign out everywhere"; not bumped on passkey deletion.
- **Affected:** `TokenService.php:25-56`, `AuthService.php:67-84`, `AuthController.php:134-138`, `frontend/src/lib/api.ts:23-31`
- **Fix:** hashed `jti` rows with token family, rotation + reuse detection, absolute session lifetime, revoke on logout, "sign out all" bumps `tokenVersion`.
- **Notes:** CWE-613.

### M7 — Unbounded input/quotas and O(n²) ICS rendering  [BACKEND-F6]

> **Status (git-log check 2026-10-15): PARTIALLY FIXED** — caps of 5000 events per import/bulk (`8913ce8`) and 366 per series (`eacd4d0`); constant query count for public feed list/ICS (`66eea14`). **Still open: `preg_replace` ICS post-processing, unbounded `listEvents`/`dates`, quotas.**
- **Scope:** authenticated user creates data; unauthenticated public feed triggers cost
- **Description:** no quotas on clubs/calendars/events/locations; `from-template` `dates` and `Input::idList` unbounded (one `find()` per id); `listEvents`, public `getFeedEvents`/`getFeedIcs` load everything unwindowed with N+1; `buildIcs` runs `preg_replace` over the whole string per located event (measured 0.29 s at 2000 events, 1.8 s at 5000, per unauthenticated request). `preg_replace` returning null → TypeError 500.
- **Affected:** `IcsService.php:46-66`, `PublicFeedService.php:20-100`, `EventService.php:27-100`, `Input.php:84-100`, `EventController.php:50-62`
- **Fix:** cap lists/dates, add quotas, date window or pagination, drop regex post-processing (fixes M3), ETag/Cache-Control + per-IP limit on feeds, eager joins.
- **Notes:** CWE-400/770.

### M8 — Members added without consent; enumeration and name disclosure  [AUTHZ-F2, AUTH-6]
- **Scope:** any authenticated user (can create their own club)
- **Description:** `POST /clubs/{id}/members` adds any registered user immediately (no invitation), returns id/name/e-mail; 201 vs 404 confirms accounts. Combines with H1, H4.
- **Affected:** `ClubController.php:89-101`, `ClubService.php:86-103`
- **Fix:** invitation flow (token mail, accept to join); uniform response without names; rate limit; admin role.
- **Notes:** CWE-204/359/862.

## INFO / hardening

- **I1 Deploy hardening** [BACKEND-F12]: no SSH host-key pinning (password captured on MITM), `DEPLOY_PASSWORD` in plaintext root `.env` (untracked) and process env, no pre-flight check of server `.env.local`/`config/jwt/*.pem` modes or placeholder values, JWT passphrase defaults to `APP_SECRET`, migrations run before publish. Prefer key auth + `StrictHostKeyChecking=yes`. (`deploy.php:57-73`, `deployer_recipe.php:41-119`)
- **I2 Mapbox tokens in git history**: older public `pk.` token in `frontend/src/components/locations/MapPicker.tsx` (commits e0bbc0a..550fb55); `mapbox-tokens.txt` was committed in 16277e9 (**not tracked at HEAD** — two agents wrongly said it still is). Gitleaks reported 1 hit (the MapPicker one). Public tokens are client-side by design, but restrict by URL and rotate if the same token is the server `MAPBOX_TOKEN`; history rewrite optional.
- **I3 `.htaccess`**: no `Options -Indexes -MultiViews`, no deny for `*.env/*.pem/*.log` beyond dotfiles; confirm sourcemaps off (frontend agent saw none in the build). [BACKEND-F13]
- **I4 Misc backend**: fixtures password `password123` (dev only); `PruneUnverifiedUsersCommand` not scheduled; refresh token is hand-rolled HS256 JWT with standard base64 rather than base64url; `OidcProvider::parseIdToken` doesn't validate signature/iss/aud/nonce (OK: token from token endpoint over TLS) and no PKCE; local `config/jwt/public.pem` is 0666; 404-vs-403 existence oracle on IDs (UUIDv7, not guessable); `lastClubId/lastCalendarId` unvalidated in `PATCH /me`. [BACKEND-F14, AUTH-Info, AUTHZ-F8/F9]
- **I5 Frontend**: route guards client-side only (backend enforces); IDs placed into API paths without `encodeURIComponent` (`useCalendarData.ts:48`, `api.ts:178`); OAuth provider id into href unencoded; legacy `accessToken` storage key still read. [FRONTEND-F7/F9, F4]

## Scanner results (verified by lead)

- **composer audit --locked:** clean (0 advisories).
- **semgrep (php, security-audit, ts, react, owasp-top-ten):** 0 findings.
- **gitleaks:** 1 hit = historical Mapbox token (I2).
